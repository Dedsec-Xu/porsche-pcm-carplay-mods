# Build and deployment record

## Local inputs

The directory layout deliberately matches the development scripts. Place these private inputs in the repository root; Git ignores them:

- `P3645-lsd.jar`: locally converted from the matching unit's `/ifs/lsd.jxe`.
- `hmi-java/de/audi/tghu/tone/hmi/pgen2high/ToneScreenBag1.java`: CFR output from that input.
- `P3645-dio_manager`: matching original native binary.
- `P3645-dio_manager.duck-disabled`: generated by `patch_disable_duck_event.py` (requires `capstone` and `pyelftools`).

Use JDK 8, Python 3, and ASM 9.7 (`asm`, `asm-tree`, `asm-analysis`). Set `JAVA8_HOME` to the JDK root and `ASM_CP` to the ASM JAR classpath or a directory wildcard. Run:

```powershell
./sound-control/build.ps1
```

The native rotary popup source is generated from the local decompilation and remains ignored. The resulting JAR contains firmware-derived classes and is also ignored. Rebuilds may differ in ZIP timestamps; use the recorded hash only for the artifact installed during the session.

## Target loading preflight

`DeviceLoadCheck` uses `Class.forName(..., false, ...)` and reflects method declarations without initializing the HMI applications. Compile it with `-source 1.3 -target 1.2`, package it, and transfer it and the candidate to `/tmp` on the unit.

Example command, using the examined unit's J9 paths:

```sh
LD_LIBRARY_PATH=/ifs/jre/bin /ifs/jre/bin/j9 -verify -Xmx8m \
  -Xbootclasspath:/tmp/device-check.jar:/tmp/pcm-prompt-rotary.jar:/ifs/lsd.jxe \
  DeviceLoadCheck de.audi.app.terminalmode.smartphone.carplay.CarPlayDSIManager pcm.PromptRuntime
```

The session also checked ToneModelBank, DSISoundHandler, DSISoundListenerImpl, ToneScreenBag1, ToneScreenFactory, PromptLevelPanel, and PromptRotaryPopup. This is a loading check, not a substitute for UI and playback testing.

## Deployment scripts are session-specific

`deploy.py` is the recorded installer, not a general-purpose flash tool. It assumes Telnet access, an existing verified original `dio_manager.duck-stock` backup, and a currently installed no-duck binary. It requires `PCM_PASSWORD` in the environment; no password is provided. Host addresses are the private LAN used during development. File transfers use a temporary FTP server at `172.16.250.100:2121`, rooted at this repository.

- `install` records the initial horizontal-slider artifact workflow, which was superseded. Do not recreate it for use.
- `install-rotary` installs `pcm-prompt-rotary.jar` under the on-unit name `pcm-prompt-level.jar`. It expects the existing `dio_manager.before-prompt-slider` recovery backup and verifies its hash. It stages transfers and verifies readback hashes.
- `rollback` disables `pcm-prompt-level.jar` and restores `dio_manager.before-prompt-slider` through a temporary file. It does not reboot automatically.

The session used this reboot command after installation or rollback:

```sh
on -f rcc /usr/apps/mib2_ioc_flash reboot
```

No firmware upgrade was performed. The repository does not automate establishing the initial recovery backups. Keep raw error archives, process command lines, vehicle identifiers, and credentials out of Git.
